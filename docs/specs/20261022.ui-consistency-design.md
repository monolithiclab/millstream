# Web UI consistency: design

## Why

The web UI grew screen by screen across M3. Each screen solves the same problems (where the pipeline name goes, where
filters sit, how state tabs look, where the explanation goes) a little differently, so a person relearns the layout
on every screen. Four bugs also make the first minutes feel broken. The goal is a UI that is highly homogeneous, easy
to read and quick to learn: one page anatomy, one control per job, help out of the way.

## Goals

- Every screen follows one page anatomy (below), built by `ScreenPage`, so the same thing is always in the same
  place.
- One component per job: one select, one state-tab control, one filter row, one card heading, one help toggle.
- Inline explanations leave the page body and move into a `(?)` toggle next to the title.
- The four bugs found in the audit are fixed, each with a test that fails without the fix.

## Non-goals

- No new screen, feature, API route or data. The HTTP API is untouched.
- No new visual identity: tokens (`tokens.css`), fonts and the canvas's look stay. This is consolidation.
- No redesign of the graph canvas, the run timeline, the diff viewer or the inbox review panel beyond their page
  frame.

## Anti-goals

- A screen that needs a special case in `ScreenPage`. If a screen does not fit the anatomy, the anatomy is wrong or
  the screen is; fix one of them.
- Help hidden so well that a first-time user cannot find it: the `(?)` is always visible next to the title.
- Lost accessibility: the axe suite (WCAG 2.2 AA) and keyboard paths keep passing.

## Audit (2026-10-22, live server at :7070, Chrome on macOS)

Inconsistencies:

| Concern | What the screens do today |
| --- | --- |
| Context line above the title | none (workspace screens), `m2-fixture` in mono (Runs, Insights, Improve, Lessons), `Pipeline m2-fixture` (Graph, Items, Dead letters), a breadcrumb (Run, Item) |
| State tabs | `Segmented` beside the title (Insights, Improve), `Segmented` under it (Graph, Dead letters), a full-width tab bar (Runs), tabs inside a card (Item) |
| Figures | beside the title (Nodes, Inbox), on a line under it (Pipelines, Dead letters) |
| Filters | unlabeled selects beside the title (Inbox), labeled fields in a row (Logs, Metrics), a card with an Apply button (Items) |
| Explanations | right-aligned small text (Pipelines, Graph, Insights, Lessons), a paragraph plus a note (Improve), under a field (Items) |
| Primary action | top right (Runs, Improve), right of the tabs (Dead letters), inside cards (Insights) |
| Selects | the sidebar switcher (custom button), the theme and language selects (native, chevron touching the border), filter selects (native, `field` class) |

Bugs:

1. **Metrics chart empty on load.** The chart frame renders with no series until a series is unchecked and checked
   again in the table below it.
2. **Select chevron overlaps the border.** The theme and language selects in the sidebar draw Chrome's native arrow
   against the right border on macOS; the other native selects share the risk.
3. **"All pipelines" switcher empty on first run.** The shell loads the pipeline list once; pipelines applied after
   the page loaded never appear until a reload. `PipelineSelect` fetches its own copy, so the two lists can disagree.
4. **Run page stuck loading after a few page loads.** Each page holds one or two server-sent event streams; over plain
   HTTP/1.1 Chrome allows six connections per host, and sockets of left pages drain slowly (observed: 7 open, 3 after
   a minute), so ordinary requests queue behind them. Several open tabs hit the same cap. The fix (one multiplexed
   stream per tab, or HTTP/2) changes the HTTP API, so it is **out of scope** here and parked in `ROADMAP.md`.

## The page anatomy

`ScreenPage` renders every screen top to bottom as:

1. **Context line** (optional): the breadcrumb of the screen's parents, one form everywhere: links separated by `/`,
   the pipeline name in mono. Pipeline screens show `<pipeline>`; detail screens show `<pipeline> / <Section>`
   (Run: `m2-fixture / Runs`; Item: `m2-fixture / Streams and items`; Proposal: `m2-fixture / Improve`). Workspace
   screens (Pipelines, Inbox, Nodes, Metrics, Logs) have none.
2. **Title row**: the h1, then the help toggle `(?)` when the screen has help, then status chips (a run's or an
   item's state); the screen's primary actions sit at the right end of the row and wrap under it on narrow screens.
3. **Summary line** (optional): the screen's figures in one line of small text under the title (`2 pipelines · 0
   running · 4 open dead letters`, `0 of 4 slots busy · 1 node`, `0 to review · 0 sampled`).
4. **Toolbar** (optional): state tabs first (one `Segmented`, counts in the labels), then filters, then bulk or
   secondary actions at the right end. One row, wrapping.
5. **Content**: cards, tables and lists, with the shared loading, empty and error states.

`ScreenPage` takes these as named props (`context`, `help`, `status`, `actions`, `summary`, `toolbar`) instead of
today's free-form `eyebrow` and `header`, so a screen cannot place them elsewhere.

## Components

- **Help toggle** (`HelpTip`): a 20 px `(?)` button after the h1, labeled "About this page" for screen readers. A click
  or Enter opens a small popover under it holding the screen's explanation (text and inline code); Escape, a click
  outside or a second click closes it. Escape returns focus to the button; an outside click leaves focus where it
  landed. It is a disclosure (button with `aria-expanded` and `aria-controls`), not a hover tooltip, so it works by
  touch and keyboard. Fields with their own
  help (the Items `Where (CEL)` field) use the same toggle after their label.
- **Select**: one styled select for every dropdown (filters, theme, language): native `<select>` with
  `appearance: none`, the switcher's chevron drawn inside the padding, the same height as text fields. The sidebar
  switcher keeps its disclosure (it navigates) but shares the look.
- **Filter field**: label above, 34 px control, in the toolbar. Selects apply on change, text fields on Enter or blur.
  No Apply button (Items' Apply goes).
- **State tabs**: `Segmented` everywhere, Runs' tab bar included, with counts where the screen knows them.
- **Card heading**: `cardTitle` (serif) for every section card's title (an insight's headline, a dead-letter group's
  error and other in-card headlines keep their own sizes); identifiers inside a card stay mono at body size
  (Lessons' step cards use the serif title with the step name in mono beside it).

## Bug fixes

1. Metrics renders its series on first load (test: the chart receives the series without a toggle).
2. The shared Select fixes the chevron (test: a Playwright check that the arrow's box lies inside the control on
   Chromium; the visual review covers both themes).
3. One pipeline list for the shell and every `PipelineSelect`, refetched when the switcher opens and on window focus
   (test: a pipeline added to the fake API after load appears when the switcher opens).
4. Parked in `ROADMAP.md`, with the reproduction above.

## Testing

- Unit (Vitest, fake timers, `FakeApi`): `HelpTip` (open, close by Escape and outside click, focus return, labels),
  `Select`, `ScreenPage`'s slots, the switcher refetch, the metrics first render.
- A structural test over every route: each screen's page renders its h1 inside the anatomy, help (when present)
  only in `HelpTip`, and no text left in the old right-aligned explain position.
- Playwright and axe (`make test-ui-e2e`): every screen in both themes passes axe; the help toggle works by keyboard;
  a phone-width pass (390 px) shows no horizontal scroll on any screen.
- A visual review in Chrome of every screen, both themes, desktop and phone width, before closing.

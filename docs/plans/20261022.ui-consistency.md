# Web UI consistency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screen of the web UI follows one page anatomy built by `ScreenPage`, uses one control per job, keeps
its explanation in a `(?)` toggle, and the three UI bugs of the audit are fixed.

**Architecture:** `ScreenPage` gains named slots (`context`, `help`, `status`, `actions`, `summary`, `toolbar`) and
renders them in a fixed order; two new shared components (`HelpTip`, `Select`) replace the per-screen variants. The
screens migrate onto the slots in two batches, then the old `eyebrow` and `header` props go.

**Tech Stack:** React, TypeScript, Tailwind (token utilities only), react-i18next, Vitest, Playwright + axe; all run
in containers (`make test-ui`, `make test-ui-e2e`), never on the host.

**Spec:** `docs/specs/20261022.ui-consistency-design.md`

## Global Constraints

- No Node on the host: `make test-ui` (typecheck, lint, format, Vitest, i18n checks) and `make test-ui-e2e` run in
  containers. `FILES=` narrows `make test-ui`.
- Only token utilities: every colour, font, radius, shadow and motion comes from `ui/src/styles/tokens.css`.
- i18n: `t()` takes literal keys of `src/i18n/en.json`; every new key exists in `en.json` and `fr.json`; French
  needs a no-break space before `: ; ! ? »`.
- Unit tests use fake timers and the `FakeApi`, never the network or a wall-clock wait.
- Existing i18n texts keep their wording; only their position changes.
- No HTTP API change. No new dependency.
- Gate per task: `make test-ui` and `make ci` green. Agents never run `make test-ui-e2e`, `make test-e2e` or
  `make soak`.
- Commits: `type(scope): summary` (scope `ui`), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A French label 30 % longer than the English one must wrap inside the title row and toolbar, not overflow
  (Task 3 and 4 tests render one screen in French).
- A screen opened by URL with filters in the query keeps them after the move into the toolbar (Task 3: Logs and
  Metrics URL tests stay green).
- Keyboard: the help toggle opens with Enter, closes with Escape and returns focus (Task 1 test).
- Phone width (390 px): toolbar and actions wrap with no horizontal page scroll (Task 5 Playwright check).
- A pipeline applied after the page loaded appears in the switcher and every pipeline filter (Task 2 test).

### Task 1: Page anatomy and shared components

**Files:**
- Create: `ui/src/common/HelpTip.tsx`, `ui/src/common/HelpTip.test.tsx`
- Create: `ui/src/common/Select.tsx`, `ui/src/common/Select.test.tsx`
- Create: `ui/src/common/Breadcrumb.tsx` (or inside `ScreenPage.tsx` if under 30 lines)
- Modify: `ui/src/screens/ScreenPage.tsx`, its test (create `ScreenPage.test.tsx` if none)
- Modify: `ui/src/i18n/en.json`, `ui/src/i18n/fr.json` (`help.toggle`: "About this page" / "À propos de cette page")

**Interfaces (produces):**
- `HelpTip({ label?: string; children: ReactNode })`: a disclosure button (20 px `(?)`, `aria-expanded`,
  `aria-controls`, accessible name `label ?? t('help.toggle')`) and a popover under it (max width ~320 px, kept in the
  viewport, `card` look, small text). Closes on Escape, outside click (reuse `shell/useDismiss`) or a second click;
  focus returns to the button.
- `Select(props: SelectHTMLAttributes<HTMLSelectElement>)`: a native `<select>` with `appearance-none`, the
  switcher's chevron (`M3 4.5L6 7.5L9 4.5`) absolutely placed inside right padding, `min-h-[34px]`, the `field` look;
  `className` applies to the wrapper width.
- `Breadcrumb({ items: { label: string; to?: string; mono?: boolean }[] })`: links separated by `/`, small text,
  pipeline names mono.
- `ScreenPage({ title, context?, help?, status?, actions?, summary?, toolbar?, children })` renders, in order: the
  context line; the title row (h1, `HelpTip` holding `help` when given, `status`, then `actions` pushed right with
  `ml-auto`, wrapping); the summary line (`text-small text-ink-2`); the toolbar (one flex-wrap row, `items-end`); then
  children. Keep `eyebrow` and `header` working until Task 4 removes them.

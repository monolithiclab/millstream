# M6 release pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `brew install monolithiclab/tap/millstream`, `curl … install.sh | sh` and
`docker pull ghcr.io/monolithiclab/millstream` install a signed Millstream release, and a scaffolded action builds
against the published Go SDK with no `replace`.

**Architecture:** GoReleaser (already configured for snapshots) gains a Homebrew formula and a tag-triggered release
workflow modelled on gomddoc's. Every pull request builds a full snapshot and smoke-tests its image and its install
script, so a tag only repeats what CI already proved. A `verify` job after publication checks the signatures, the
published image, the install script and the Homebrew formula on fresh runners. A release candidate tag rehearses
everything except the Homebrew upload.

**Tech Stack:** GoReleaser v2.18.3 and syft (pinned in `tools/release/go.mod`), cosign v3 keyless, GitHub Actions,
GHCR, POSIX sh.

**Spec:** `docs/specs/20261116.m6-release-design.md`, section 1 (Release). Sections 2 to 7 are later M6 plans.

## Global Constraints

- Every action pinned to a 40-hex SHA with a `# vX.Y.Z` comment, every `FROM` by `@sha256:` (`make lint-pins`).
  Reuse the SHAs and digests already in `.github/workflows/ci.yml` and in gomddoc's `release.yml`
  (`../gomddoc/.github/workflows/release.yml`) rather than resolving new ones.
- Workflows: `permissions: {}` at workflow scope with job-level grants, `persist-credentials: false` on every
  checkout, a `timeout-minutes` on every job.
- GoReleaser runs from `tools/release/go.mod` (v2.18.3) locally and in CI alike: one pinned version, never
  `goreleaser-action`'s own download.
- The Homebrew token exists only as the `HOMEBREW_TAP_TOKEN` repository secret (already set). Never in a file, a
  command line or a log.
- A `v*` tag (and `sdk/go/v*`) is pushed only when Nicolas says so. The prerelease `v0.1.0-rc.1` comes before `v0.1.0`.
- No customer, prospect or partner names anywhere (AGENTS.md). Commits are `type(scope): summary`.
- Agents run `make ci` and only the targeted slow commands named in their task; the full `make test-e2e` runs once,
  at Task 5.
- A doc that owns changed behaviour changes in the same commit (`docs/guides/deployment.md` for the artefacts,
  the quickstart and getting-started for install steps).

## Review Focus

1. A prerelease tag (`v0.1.0-rc.1`): the image gets no `latest` tag, Homebrew is skipped, the GitHub Release is
   marked prerelease. Task 3's verify job asserts `latest` still points elsewhere (or is absent) after an rc.
2. A tag on a commit that is not on `main` is refused before anything is built (Task 3 ancestry step).
3. `install.sh` on macOS: no `sha256sum` (only `shasum -a 256`) and no cosign. It verifies the checksum, warns about
   the signature, and installs; `MILLSTREAM_REQUIRE_COSIGN=1` aborts instead. Task 2 tests both without cosign.
4. `install.sh` when `/usr/local/bin` is missing or not writable (Apple Silicon without sudo): it falls back to
   `~/.local/bin` and prints a `PATH` hint. Task 2's test runs with an unwritable default.
5. A scaffolded action outside any checkout: `go mod tidy && go build` must fetch `sdk/go v0.1.0` from the proxy.
   Task 3's verify job scaffolds and builds an action with the released binary.

### Task 2: Install script

**Files:**
- Create: `scripts/install.sh` (adapted from `../gomddoc/scripts/install.sh`)
- Create: `scripts/test-install`
- Modify: `Makefile` (`lint-shell` adds `scripts/install.sh` with `-s sh`, and `scripts/test-install`;
  `test-release` runs `scripts/test-install`)

**Interfaces:**
- Consumes: `dist/` from `make release-snapshot` (Task 1): `millstream_0.0.0-snapshot_<os>_<arch>.tar.gz` and
  `SHA256SUMS`.
- Produces: `install.sh` honouring `MILLSTREAM_VERSION` (with or without `v`, default latest),
  `MILLSTREAM_INSTALL_DIR` (default `/usr/local/bin`, falling back to `~/.local/bin`),
  `MILLSTREAM_REQUIRE_COSIGN=1`, and `MILLSTREAM_BASE_URL` (default
  `https://github.com/monolithiclab/millstream/releases/download`; when set, `MILLSTREAM_VERSION` is required and
  the GitHub API lookup is skipped, and the file names the tag as given). Document `MILLSTREAM_BASE_URL` in the header
  as "for testing and mirrors".

- [ ] **Step 1:** Write `scripts/test-install` (bash): serve `dist/` with `python3 -m http.server` on a free loopback
  port. Run `install.sh` with `MILLSTREAM_BASE_URL`, `MILLSTREAM_VERSION=0.0.0-snapshot` and a temporary
  `MILLSTREAM_INSTALL_DIR`, with cosign hidden from `PATH`. Assert that the binary exists, that `millstream version`
  prints `millstream 0.0.0-snapshot`, and that stderr names the missing signature check. Add three more cases: with
  `MILLSTREAM_REQUIRE_COSIGN=1` it exits non-zero and installs nothing; with a corrupted copy of `dist/` (one byte of
  the archive changed) it exits non-zero naming the checksum; with an unwritable install directory and no
  `MILLSTREAM_INSTALL_DIR` it installs into `$HOME/.local/bin` (`HOME` set to a temporary directory) and prints a
  `PATH` hint. The default `/usr/local/bin` is read from a variable the test can point at an unwritable directory:
  `MILLSTREAM_DEFAULT_DIR`, internal and undocumented.
- [ ] **Step 2:** Run it to see it fail (no `install.sh` yet).
- [ ] **Step 3:** Adapt gomddoc's `install.sh`: `REPO=monolithiclab/millstream`, `BINARY=millstream`, the variables
  above, and cosign identity `^https://github.com/monolithiclab/millstream/`. Drop the fallback to the old
  `.sig`/`.pem` pair: millstream has only ever signed bundles. Keep the `sha256sum`-or-`shasum -a 256` choice.
- [ ] **Step 4:** `scripts/test-install` passes; `make lint-shell` passes (`shellcheck -s sh scripts/install.sh`).
- [ ] **Step 5:** `make ci` green, `make test-release` green (run_in_background).
- [ ] **Step 6:** Commit: `feat(release): install script verified against checksums and the cosign bundle`.

### Task 3: Release workflow

**Files:**
- Create: `.github/workflows/release.yml`
- Modify: `.github/dependabot.yml` (add `gomod` for `/`, `/sdk/go`, `/tools` and `/tools/release` with prefix
  `chore(deps)`, and `docker` for `/` with `chore(docker)`, grouped minor/patch as in gomddoc's)

**Interfaces:**
- Consumes: `ci.yml` via `workflow_call` and `make release` (Task 1); `scripts/test-image <image> <node image>
  <version>` (Task 1); `scripts/install.sh` (Task 2).

- [ ] **Step 1:** `release.yml`, on `push: tags: ['v*.*.*', 'v*.*.*-*']`, `permissions: {}`. Three jobs:
  - `ci`: `uses: ./.github/workflows/ci.yml` with `contents: read`. That runs `make ci`, `test-e2e`, the UI suites,
    the image job and `test-release`.
  - `goreleaser` (`needs: ci`, timeout 45, `contents: write`, `packages: write`, `id-token: write`). It starts with
    gomddoc's tap-token preflight copied verbatim (TAP `monolithiclab/homebrew-tap`), then checks out with
    `fetch-depth: 0` and `persist-credentials: false`. It refuses a tag not on main
    (`git merge-base --is-ancestor "$GITHUB_SHA" origin/main`), then runs setup-go, buildx, the GHCR login,
    cosign-installer v4.1.2 and `make release`. Its env holds `GORELEASER_CURRENT_TAG: ${{ github.ref_name }}`,
    `GITHUB_TOKEN` and `HOMEBREW_TAP_TOKEN`, each with gomddoc's comments. Use the pinned tools instead of
    `goreleaser-action` or `download-syft`.
  - `verify` (`needs: goreleaser`, `contents: read`, `packages: read`), as a matrix over `ubuntu-latest` and
    `macos-latest`, with timeout 20. Each runner installs cosign. It downloads `SHA256SUMS` and its bundle with
    `gh release download`, then runs `cosign verify-blob` with the deployment guide's identity and issuer. It runs
    `MILLSTREAM_VERSION=${GITHUB_REF_NAME} MILLSTREAM_REQUIRE_COSIGN=1 sh scripts/install.sh` into a temporary
    directory and checks `millstream version`. In that temporary directory it runs `millstream init action greet`
    (check the real command with `millstream help init`), then `go mod tidy && go build ./...` with setup-go. That
    proves the published SDK resolves (Review Focus 5).
    - Ubuntu only: log in to GHCR, run `cosign verify` on the image with the same identity, then
      `scripts/test-image ghcr.io/monolithiclab/millstream:${version} <UI_NODE_IMAGE> ${version}`. On a prerelease,
      assert that `docker manifest inspect ghcr.io/monolithiclab/millstream:latest` fails or names a different
      digest (Review Focus 1).
    - macOS only, and only for a non-prerelease tag: `brew install monolithiclab/tap/millstream && millstream
      version`.
- [ ] **Step 2:** `make ci` (lint-pins covers the new workflow). Check the workflow with `actionlint` if it's
  available in `tools/go.mod`. If not, don't add it: say so in the report.
- [ ] **Step 3:** Commit: `ci(release): tag-triggered release, signed, verified on fresh runners`.

## Execution notes

(Filled in when the plan is done: what was built, the rulings, what was deferred.)

Rulings made while planning:

- The root module keeps its `replace` of `sdk/go`. `go install github.com/monolithiclab/millstream/cmd/millstream@…`
  is therefore not an install path. A committed `go.work` would conflict with `go tool -modfile=tools/go.mod` in the
  canonical `common.go.mk`. Homebrew, the install script, the image and a source build cover installation.
- The quickstart runs from Homebrew or the install script, not from the image: the distroless runtime runs static
  binaries only, and the example crawler is Python.
- Spec section 1 says the release workflow tests that the binary serves the built `index.html`. That check runs on
  the snapshot image in CI (`make test-release`) and again on the published image in `verify`.
- The spec's "ROADMAP release and SDK items move here" has nothing left to move: the ROADMAP's Deployment (icebox)
  holds no release or SDK item today.
- No QEMU in the release: `Dockerfile.release` copies a prebuilt binary and runs nothing.

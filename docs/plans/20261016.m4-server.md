# M4 server: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Each task is test-first,
> ends with a green `make ci` and its own commits.

**Goal:** Millstream runs as a server: a Postgres store, `serve` with a hot standby that takes over on failure,
remote nodes that join with the node token, packages applied as revisions and rolled back, pipelines importing each
other's streams, webhook triggers, token auth, Prometheus metrics, retention and purge, and VPS packaging.

**Architecture:** the `store.Store` interface gets a second implementation on Postgres (pgx), behind the same writer
loop and units; one conformance suite runs every store test against both. Leadership is a Postgres session advisory
lock held on the engine's only write connection. Remote nodes speak a small HTTP/2 JSON protocol to the active engine
(register, pull, heartbeat, done, error, package and artifact fetches scoped to held leases), the same transport
interface the embedded node already uses in memory. Shared streams are one more atomic unit inside Done. Retention
and purge are store units run by engine jobs.

**Tech stack:** Go as before; `github.com/jackc/pgx/v5` for Postgres; Postgres 17 in tests through the official image
pinned by digest (tagged tests only); an S3-compatible artifact store through the minimal AWS SigV4 client already
justified or MinIO's client (choose the smaller and say why), MinIO pinned by digest in tagged tests; Prometheus text
exposition (already written in M2).

**Spec:** [platform design](../specs/20261014.platform-design.md), sections 4.6 (webhook triggers), 4.12, 5.9, 5.10,
5.11 (Stream import), 9.1–9.3, 10.2, 14, 15.2, 15.7, 17 and 19 (M4 row).

## Global constraints

- Everything from the M1–M3 plans' Global constraints still applies, including AGENTS.md "Test suites": the default
  Go suite stays within `make test-times`; anything that needs Postgres, MinIO, a real listener, TLS, processes,
  Docker or `-race` goes behind the `e2e` tag. SQLite remains the default store and the default suite's store. The
  suite starts M4 at 418 ms against the 400 ms working target: each task makes room for what it adds.
- UI changes follow the M3 rules: `make test-ui` and `make test-ui-e2e` green, axe clean, English and French.
- No compatibility shims: the M1–M3 SQLite schema may change freely; Postgres starts from the same logical schema.
- Every unit keeps its failpoints on both stores; the crash matrix runs on SQLite (default e2e) and on Postgres.
- Security defaults: the API refuses non-loopback listening without `auth.token`; nodes require TLS except on
  loopback; tokens compared in constant time and never logged.

## Review focus

1. Failover while a batch is mid-commit: the standby takes over, nothing is applied twice, every node resumes, and a
   stale node's `done` is refused by fencing (Task 3).
2. A node partitioned for longer than the lease: its deliveries go to another node; when it reconnects, its buffered
   results are refused and it releases cleanly (Task 4).
3. A producer replay or cancel while an importer is paused: consumer runs receive exactly the producer run's items,
   once, and settle (Task 5).
4. Retention running while a review sample or dead letter still needs a payload: the payload is kept (Task 8).
5. Purge interrupted by a crash midway across two pipelines linked by an import: it resumes and finishes, and no
   lease is granted on fenced lineage meanwhile (Task 8).

## Tasks

### Task 1: Postgres store and the store conformance suite

- `internal/store/postgres` implementing `store.Store` with the same writer loop design (single write connection,
  group commit, savepoints per unit, event sequence in commit order), read pool, migrations from the same logical
  schema, `now()` as the clock for leases and deadlines.
- Refactor store tests into a conformance suite run against SQLite (default build) and Postgres (e2e tag, a
  container per test binary with a fresh database per test via template databases).
- Failpoints and the crash matrix on Postgres.
- Environment file `store: { postgres: { dsn: { env: … } } }` or `{ sqlite: { path } }`.

### Task 2: environment file, `serve`, `apply`, `rollback`, `disable`

- Parse every spec 14 key strictly (no more "not supported yet"), secrets per pipeline from the environment.
- `millstream serve`: engine from the environment file (store, listen, auth, embedded node, artifacts); `apply <dir…>`
  uploads packages by hash as new revisions over the API (or directly to the store with `--direct`), validating
  across pipelines; `rollback <pipeline> [revision]`; `disable`; API endpoints and UI actions for rollback and disable
  (deferred from M3).

### Task 3: standby engine and failover

- Advisory lock leadership on the write connection; a standby blocks on it, then rebuilds in-memory state and
  dispatches; step down at once when the write connection fails; TCP keepalives; `/api/v1/nodes` shows active and
  standby engines.
- Failover chaos tests (e2e): kill the active engine at every unit boundary and at random points with two engines and
  a node; check the store against the clean reference as the crash suite does.

### Task 4: remote nodes

- `millstream node --join <url>` with `MILLSTREAM_NODE_TOKEN`, TLS (engine certificate configured in the environment
  file; a self-signed development mode on loopback only), registration (id, version, labels, capacity per runtime,
  `--allow-exec`), pull, heartbeat every 5 s, done/error with fencing, package fetch by hash and signed artifact URLs
  only for held leases (engine proxy for the local artifact directory; S3 presigned URLs with an S3 store), buffered
  results resent after reconnect, following the active engine across failover, `node drain` and SIGTERM, `nodes
  revoke`.
- Builtins stay in the engine (M2 ruling); placement by labels and runtimes; unschedulable deliveries counted and
  shown (API, UI Nodes screen, insight).
- Node chaos tests (e2e): kill nodes, partition them (proxy that drops traffic) past the lease, revoke, rotate the
  token.

### Task 5: shared streams

- `streams: { name: { pipeline, stream } }` imports; `check`/`apply` across pipelines: contract compatibility (4.11),
  refuse removing an imported stream or breaking a contract without `--force`, refuse cycles.
- The Stream import unit inside Done (copies with deterministic ids and parent links; one consumer run per producer
  run, open until the producer run settles); paused or disabled consumers still receive; cancel and replay semantics;
  `replay --stream <name> --since` back-fill over retained producer items; lineage across pipelines in API and UI.

### Task 6: limits, round-robin and webhook triggers

- Verify pipeline `limits` and round-robin across pipelines under many pipelines and remote nodes (M1 implemented them
  for one engine; extend tests to the server).
- Webhook triggers: token per trigger generated at `apply`, stored hashed, `trigger token --rotate`, request ids,
  payload validated against the trigger schema, rate limiting per token; API route outside `/api/v1` auth (token in
  the path or header).

### Task 7: token auth and Prometheus

- `auth.token`: bearer token on the API and UI (login page storing the token in memory or a cookie with `HttpOnly`,
  `SameSite=Strict`), required for any non-loopback listener; reviewer identity from the token's configured name
  (single user in the open-source edition; the UI sends nothing else).
- `/metrics` Prometheus endpoint (rollups, engine and node gauges, `eval_score`, review notification failures,
  writer batch sizes), behind the same token unless `metrics.public` is set.

### Task 8: retention and purge

- Retention per stream and global (events, transcripts with compression, rollups): tombstones, batch deletes,
  keeping payloads unfinished work needs; unreferenced artifact sweep.
- `millstream purge --key|--item`: the `purges` table, fencing the lineage (no new leases, outputs discarded at done),
  deleting across imports, resuming after a crash; purge events without the erased data.
- Bounded caches flagged in M2/M3 (revision cache, engine maps) with eviction for a long-running server.

### Task 9: packaging

- Container image (distroless static, non-root, pinned by digest, built with the repo's lint-pins rules), Docker
  Compose file (Postgres, active engine, standby, a node), systemd units, GoReleaser configuration (snapshot builds
  only: no release in this phase), deployment guide in `docs/`.

### Task 10: M4 exit

- The failover and node chaos suite passes (Tasks 3 and 4) on Postgres.
- The unattended week, compressed: a soak harness (`make soak`, e2e tag) runs several pipelines, one importing
  another's stream, on the Compose deployment with a standby engine and two node containers, for a configurable
  duration (default 30 minutes; triggers every minute stand in for the reference schedule), killing the active engine
  and nodes at random intervals, and checks the store's invariants and the absence of stuck runs at the end. A real
  seven-day run is out of scope for this POC and recorded as such.

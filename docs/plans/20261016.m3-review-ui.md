# M3 review and web UI: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Each task is test-first,
> ends with a green `make ci` and its own commits.

**Goal:** people take part in pipelines and operators run them from a browser: a `review` builtin with an inbox,
reason codes, auto-approval and review samples; a versioned HTTP API with live server-sent events; and the web UI of
the design canvas, in English and French, meeting WCAG 2.2 AA, embedded in the binary.

**Architecture:** `review` is a builtin executed by the engine: its deliveries park in `awaitingReview` until a
decision unit completes them. `internal/api` serves REST under `/api/v1` from the store (reads) and the engine
(actions), plus SSE streams fed by the writer's event sequence. The UI is a Vite + React + TypeScript app in `ui/`,
built in pinned containers (`make ui`), whose `dist/` is embedded with `go:embed` and served by `millstream run`.

**Tech stack:** Go as before; React 18, TypeScript, Vite, Tailwind CSS (tokens from the canvas), React Flow, uPlot,
react-i18next, Vitest, Playwright with axe-core; the official `node` and Playwright images pinned by digest (D35).

**Spec:** [platform design](../specs/20261014.platform-design.md), sections 8, 10.2, 11.1 (reviewPattern), 12, 13,
16 and 19 (M3 row); [UI design brief](../design/20261015.ui-brief.md) and the [canvas snapshot](../design/canvas/)
(pass 0.2, version `1792076103-839e`), which is the visual source of truth.

## Global constraints

- Everything from the M1 and M2 plans' Global constraints still applies, including AGENTS.md "Test suites": Go's
  default suite stays within `make test-times` (500 ms in total, no test over 20 ms); anything slower, a real HTTP
  listener held across tests, processes, Docker or `-race`, goes behind the `e2e` tag.
- UI tests run in containers, so they cannot fit that budget: `make test-ui` runs typecheck, lint, Vitest and the
  i18n key check, `make test-ui-e2e` runs Playwright with axe; both run in CI as their own jobs and before a
  milestone closes, not in `make ci`. Vitest itself stays fast: no real timers, no network, components rendered in
  jsdom with a fake API client.
- The Go build never needs npm: a committed placeholder `ui/dist/index.html` is embedded until `make ui` replaces it;
  the built `dist/` is not committed.
- JSON keys lowerCamelCase (D18); every API change is reflected in the OpenAPI document and spec section 12.1 in the
  same commit.
- The UI uses only the HTTP API. It is localised in English and French from the first commit: no hard-coded string,
  a check fails when a key is missing in either language.
- WCAG 2.2 AA: axe reports no violation on any screen in either theme; keyboard shortcuts from the canvas's
  interaction notes; focus order and visible focus as specified there.
- No host toolchain: npm, Vite, Vitest and Playwright run only in containers (D35); CI uses the same make targets.
- Tokens, typography (Instrument Serif, Atkinson Hyperlegible Next and Mono, bundled), colours, radii and motion come
  from the canvas identity board (`docs/design/canvas/Main.dc.html`), light and dark.

## Review focus

1. A review that times out while a reviewer is editing it: `onTimeout` applies once; the late decision is refused
   with a clear message (Task 1).
2. An SSE client that reconnects with `Last-Event-ID` after missing events: it receives exactly the missing state
   events, in order (Task 2).
3. Two reviewers deciding the same item at once: one wins, the other gets a conflict, no double emit (Task 1).
4. French strings longer than English: no clipped text on any screen at 375 px or 1280 px (Task 6).
5. `prefers-reduced-motion`: pebbles freeze, no animation runs (Task 4).

## Tasks

### Task 1: the `review` builtin

- Config per spec 8: `inbox`, `timeout`, `onTimeout` (`reject`, `approve`, `escalate: <inbox>`), `editable` (JSON
  pointers), `notify` (generic webhook URL, Slack-compatible JSON with a link to the item), `display` (template),
  `reasons`, `autoApprove` (CEL), `sampleRate` (default 0.05, minimum 0.01).
- Engine: a review delivery is moved to `awaitingReview` (store unit `Park`) with its deadline; `autoApprove` matches
  publish at once and, with probability `sampleRate` (seeded, deterministic per item id), create a `review_samples`
  row.
- Store units: `Review decision` (spec 5.11: check `awaitingReview`, record decision, emit — with the edit applied
  and validated against `editable` — or filter with the reason), `Sample decision` (never emits), `Review timeout`
  (applies `onTimeout` once). Tables `reviews` and `review_samples`. Failpoints; crash matrix covers them.
- `millstream inbox [--inbox] [list|show|approve|reject|edit]`; notifications sent after commit, retried three times,
  never blocking.
- Metrics and the `reviewPattern` insight (decisions by reason code, edit hot spots, time to decision, sampled-rule
  agreement, intervention rate); the `cost` insight gains cost per approved item, deferred from M2.
- Tests: approve, edit within and outside `editable`, reject requiring a reason code, timeout each mode, escalation,
  concurrent decisions, auto-approve and samples never blocking the run, notification payload and retries
  (httptest), crash cases.

### Task 2: HTTP API and live events

- `internal/api`: `/api/v1` read endpoints (pipelines, revisions, runs and run reports, streams, items with CEL
  filter, lineage, deliveries, dead letters, metrics rollups, inbox and samples, insights, lessons, nodes) and
  actions (trigger, cancel, pause, resume, rollback when available, replay, dead letters replay and discard, review
  and sample decisions, insight acknowledge and mute). Errors as `{error: {code, message}}`.
- OpenAPI 3.1 document `internal/api/openapi.yaml`, served at `/api/v1/openapi.yaml`; contract tests check every
  route and response against it.
- SSE: `/api/v1/live/pipelines/{p}` (coalesced per-step state snapshots, about 4 per second),
  `/api/v1/live/runs/{r}`, `/api/v1/live/items/{i}` (state events with sequence ids, `Last-Event-ID` resumption,
  `409 snapshot required` when older than retention), `/api/v1/live/logs` (best effort, gap marker after reconnect,
  fed by node log relay of the embedded node).
- Handler tests call the handler through `httptest.NewRecorder` on an in-memory store; SSE tests drive the broker
  with an injected clock and a fake event source, never wall-clock waits.
- `millstream run` serves the API and UI on `listen` (default `127.0.0.1:7070`); no auth on localhost in M3 (token
  auth is M4) — refuse non-loopback listen addresses until then.
- Tests: handler tests per route, contract tests, SSE resumption with a missing range, coalescing rate, log gap
  marker.

### Task 3: UI scaffold, tokens, i18n, containers

- `ui/` with Vite + React + TypeScript + Tailwind; `make ui` builds in the pinned `node` image; `make test-ui` runs
  typecheck, ESLint, Vitest and the i18n key check; `make test-ui-e2e` runs Playwright in the pinned Playwright image
  against a Linux `millstream` binary started inside that container on a seeded database; CI runs both as jobs.
- Tokens from the canvas as CSS custom properties for light and dark, mapped into Tailwind; bundled fonts.
- react-i18next with `en` and `fr`; a test fails on any missing key; `Intl` number, money and duration formatting
  per the interaction notes.
- API client generated from or typed against the OpenAPI document; SSE hook with reconnection and `Last-Event-ID`.
- App shell: navigation, pipeline switcher, command palette (`⌘K`), shortcut help (`?`), theme toggle, language
  switch, live connection state.
- `dist/` embedded with `go:embed`: a committed placeholder `index.html` keeps the Go build working before `make ui`.

### Task 4: screens part 1 (graph, item, dead letters, pipelines)

- Pipeline graph with the signature channels-and-pebbles rendering (React Flow custom nodes and edges), live overlays,
  minimap above 12 steps, side panel, keyboard navigation, reduced motion.
- Item detail: payload, artifacts preview, lineage up and down, attempts with error, transcript as a conversation,
  live logs.
- Dead letters grouped by fingerprint with replay and discard (confirmation states the consequence).
- Pipelines list with lifecycle actions.

### Task 5: screens part 2 (inbox, timeline, metrics, insights, lessons, nodes, logs)

- Review inbox desktop and 375 px, keyboard (`a`, `r` + `1`–`5`, `e`, `u` undo for 10 s), samples marked.
- Run timeline (Gantt per step, density strip, run report, ETA).
- Metrics explorer (uPlot, group by, range, view kept in the URL).
- Insights, Lessons (read-only), Nodes (embedded node and engine), Logs (live tail). The Improve view (proposals)
  arrives with M5; M3 shows insights only.

### Task 6: UI quality gates

- Vitest component tests for every component with states; Playwright end to end through the reference demo (run,
  watch the graph, open an item and its transcript, decide reviews in both languages, replay a dead letter); axe on
  every screen in both themes and both languages; visual checks at 375 px and 1280 px for clipping.

### Task 7: M3 exit

- The full reference demo from the browser, in English and French, with no axe violation: a Playwright scenario on the
  M2 agent fixture with a review step added (recorded harness), run by `make test-ui-e2e`.

## Execution notes

Milestone completed on branch `m3-review-ui` (2026-10-16). `make ci` green (coverage 89.2%); `make test-times`
418 ms median of three, under the 500 ms budget and above the 400 ms working target (printed as a warning);
`make test-e2e` green (91.0%); `make test-ui` 426 Vitest tests (98% statements, 92% branches); `make test-ui-e2e`
123 screen tests with zero axe violations across every screen, both themes, both languages, 375 and 1280 px, plus the
reference demo in English and French (about 20 s).

**Built.** The `review` builtin with the `park`, `reviewDecision`, `sampleDecision` and `reviewTimeout` units,
auto-approval with deterministic samples, escalation, webhook notifications (bounded queue, drained on shutdown,
escaped text, URL kept out of logs, optionally a secret) and `millstream inbox` (T1). The HTTP API under `/api/v1`
with its OpenAPI document, contract tests over every route and response, and server-sent events from one broker fed
by the writer (resume by `Last-Event-ID` or `?lastEventId=`, `snapshotRequired`, coalesced pipeline snapshots, a
redacted log ring) (T2). The UI scaffold: Vite, React and Tailwind built only in pinned containers, the canvas tokens
and bundled fonts, English and French with key and typography checks, the app shell, API types generated from the
OpenAPI document, embedded with `go:embed` (T3). Twelve screens: pipelines, graph with channels and pebbles, runs and
the run timeline, items list with a CEL filter, item detail with lineage and transcripts, inbox with keyboard
decisions and undo, dead letters, metrics explorer, insights, lessons, nodes and logs (T4, T5). Quality gates and the
review-focus tests (T6). The reference demo in the browser (T7).

**Rulings.**
- `millstream run` serves the API and UI on loopback only until M4's token auth; the API also refuses non-loopback
  `Host` headers (DNS rebinding) and non-JSON POSTs, and every response forbids framing (CSP `frame-ancestors`).
- Every API record except a pipeline is addressed under its pipeline, because ids are unique within a pipeline.
- Review decisions require the version the reviewer saw; the same decision resent succeeds again; reviewer identity
  is `X-Millstream-User` or the server's user until M4.
- A dead-letter replay continues attempt numbers (`attempt_base` carries the retry budget), so each attempt keeps its
  own artifacts; cancelling a run discards its open dead letters.
- The embedded UI's placeholder is `internal/ui/dist/placeholder.html`, served until `make ui` writes `index.html`,
  so a build never dirties the tree.
- UI tests run in containers in their own targets and CI jobs (`make test-ui`, `make test-ui-e2e`), outside
  `make ci`; the Go default suite is measured by `make test-times` on medians of three runs.
- The reference demo runs on `ui/e2e/demo-fixture`, the M2 fixture with a review step, replayed offline.

**Review.** The whole-branch review found no critical issue; its twelve important findings were fixed: notifications
dropped by `run --once`, webhook escaping and URL leak, attempt artifacts colliding after a replay, clickjacking,
replay-all stopping on cancelled runs, the missing items list, undo decisions lost on tab close, dialogs cut off on
small screens, duplicate live connections, demo mode in the production bundle, a listener in the default test suite,
and the noisy `test-times`.

**Deferred** (ROADMAP): rollback, disable and node drain in the API and UI (M4); items and cost today and
unschedulable deliveries; an inbox event stream (the inbox polls every 15 s); `crypto.randomUUID()` needs a secure
context for non-loopback serving (M4); the Improve view (M5); bringing the Go default suite back under 400 ms
(`Test_testPipelineCommand`, `TestRecordings`, `TestActions`).

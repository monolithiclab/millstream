# Pre-release review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Act on the 2026-11-16 codebase review before the open-source release: fix the builtin stall, cut the
unused or unusable parts of the self-improvement layer, shrink the surface a newcomer meets, add the small missing
pieces, and fold the large missing ones into an M6 design spec.

**Architecture:** Mostly deletions and renames across the CLI, the HTTP API, the UI and the spec, one engine change
(an engine-owned builtin loop), one agent-adapter change (repair turns), one new offline example and a few docs.

**Tech Stack:** Go 1.27 (stdlib first, Kong CLI), SQLite/Postgres store, React/Vite UI in containers only.

**Spec:** `docs/specs/20261014.platform-design.md` (sections cited per task). The review itself is the brief: this
plan records every ruling made on it.

## Global Constraints

- Nothing has shipped: no compatibility shims, aliases only where a task says so, no migrations for persisted data.
- Public contracts (pipeline file, action protocol, HTTP API) change with their spec section in the same commit; the
  API also with `internal/api/openapi.yaml`, then `make ui-types` and the regenerated `ui/src/api/openapi.d.ts`.
- CLI help changes: `go test ./internal/cli -run Test_help -update` rewrites the golden files.
- Commits: `type(scope): summary`, atomic, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  **Do not push**: the session pushes once at the end.
- Each commit: `make ci` green (it includes the linter), plus `make test-e2e PKG=./internal/<pkg>/...` for the
  packages the commit touches. Never a full slow suite (`make test-e2e` without PKG, `test-scenarios`, `test-ui-e2e`,
  `soak`): they run once on the merged tree. `make test-ui` runs for a commit that touches `ui/`.
- A doc that owns the changed behaviour (AGENTS.md table) is updated in the same commit; ROADMAP items a task
  resolves are removed from ROADMAP.md.
- No customer, prospect or partner names anywhere.

## Review Focus

- A pipeline whose only remote node is saturated by slow agent deliveries: its `filter`, `dedupe` and `review` steps
  keep moving (Task 1 test).
- An engine restart while a builtin delivery is leased by the engine loop: the lease expires and the delivery runs
  again once (Task 1, crash recovery via the existing failpoints).
- A user who typed `millstream dlq list` or `insights ack` from an old note: the alias still works (Task 7 test).
- A development deployment without `improve.enabled`: the UI shows no Improve entry and no request to improve routes
  fails on page load (Task 5 test).
- An agent answer that keeps failing its schema: repair turns stop at `repairTurns`, never exceed `maxTurns` or
  `maxCostUsd`, and replay from recordings deterministically (Task 10 test).

### Task 1: Builtins run in the engine, not inside a node's pull

Spec 6.4 says builtins run in the engine. Today `runBuiltin` has one caller, inside `PullWithin`
(`internal/engine/dispatch.go:75`), and a node with no free slot does not pull (`internal/node/node.go:288`); with
`MILLSTREAM_NODE_EMBEDDED: "false"` (Compose), builtins stall while remote nodes are full or absent.

**Files:** `internal/engine/engine.go` (`Run`), `internal/engine/dispatch.go`, `internal/engine/builtin.go`,
`internal/engine/nodes.go:199` (builtins carry no placement labels), tests in `internal/engine`, spec 6.4 and the
ROADMAP "Lease renewal" note (heartbeats already have their own goroutine: correct the note).

- [ ] Failing test: an engine with no node pulling (or one node with zero free slots) settles a run whose steps are
  a stubbed source then `filter` and `dedupe`; the builtin deliveries finish without any pull.
- [ ] Engine loop in `Engine.Run`: leases builtin steps only, under the engine's owner, woken by the store's
  `Changes()` and a timer at lease TTL; node pulls exclude builtin steps (`LeaseRequest.Exclude` exists). Remove the
  `completed` re-loop and the `LeaseTTL/3` bound from `PullWithin` if nothing else needs them. Builtins ignore
  placement labels.
- [ ] `make ci`; `make test-e2e PKG=./internal/engine/...` and `PKG=./internal/node/...`.
- [ ] Commit `fix(engine): run builtin steps in an engine loop, whatever the nodes' slots`.

### Task 10: Repair turns for agent answers that fail their schema

Today a schema failure is retryable and the retry renders the same prompt (`internal/agent/agent.go:290-327`).

- Manifest key `repairTurns` (default 1, 0 disables): after an answer fails the output schema, the adapter sends a
  follow-up turn holding the validator's errors, up to `repairTurns`, within `maxTurns` and `maxCostUsd`; every turn
  is in the transcript; a final failure is the existing schema-class error.
- Recordings key on the whole conversation (every prior turn), so a repair replays deterministically.
- Spec 7.1/7.2 and `docs/reference/action-protocol.md` if the manifest is documented there.

- [ ] Tests (recorded fake model): a first invalid then valid answer passes with two turns; `repairTurns: 0` keeps
  today's behaviour; the cost cap stops repairs.
- [ ] `make recordings` if keys change; `make ci`; `make test-e2e PKG=./internal/agent/...`.
- [ ] Commit `feat(agent): send schema errors back as repair turns`.

**Rulings.**

- Builtin loop wakes on the tick interval and on store changes, not on lease TTL; `PullWithin` keeps its stub
  re-loop and `LeaseTTL/3` bound for stubbed and failed dispatches.
- `report` keeps `<pipeline> <run>` (run ids are unique per pipeline); `nodes drain` drains the local node.
- A duplicate open proposal is refused only between proposals answering insights; manual overlapping proposals stay
  possible.
- The demo reports improve on; the `examples/` directories stay test fixtures, with a README.
- Stock actions in M6 are built into the binary (`millstream/<name>` resolves to `millstream action <name>`), not
  OCI images; notifications go through `sink-webhook` with a body template.
- Parallel CLI tests were reverted: parallelising is the last optimisation.
- `TestM5Exit`'s cost failure and an intermittent failover cell not reached are parked in ROADMAP, not fixed:
  neither reproduced alone, and the matrix now logs engine a's exit when the second recurs.

**Gates at close.** `make ci` green on every commit. On the merged branch: `make test-e2e` passed (84 s at
close), `make test-ui` (44 s), `make test-ui-e2e` (299 s), `make soak` (31 min, `TestSoak` passed, rerun after the
node's wakeup changed). `make test-scenarios` first failed on load-sensitive races the branch made likelier: the
builtin loop doubled each engine's lease units, so Postgres write batches outran their 3 s timeout and engines
stepped down. Fixed: the embedded node wakes only when the builtin loop completed work (`Engine.Due`), the SQLite read
pool keeps its connections idle, and two tests waited or decided by an order the store does not promise. The last run
took 476 s (818 s before, 34 batch timeouts to none) and failed only `TestM5Exit`'s cost assertion, in 2 of 6 full
suites and never alone (ROADMAP). `make test-times`: 731 ms (budget 750 ms), above the 600 ms target.

**Deferred.** The per-task and final reviews left about 40 minors; the final review triaged them and three were
fixed, the rest judged not worth a change before release. Parked in ROADMAP: an environment-file key for agent
replay, a distinct `run --once` exit code for a run waiting on reviews, a leader gauge and a parked-review age metric
(alerts cannot be written without them), a Go line-length lint (comments over 120 columns recurred), the two
scenario flakes above. `make test-times` stays above the 600 ms working target on a loaded machine (731 ms; base
692 to 785 ms).
